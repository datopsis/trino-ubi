# Repository guidance

Build a security-oriented, rootless Trino image on Red Hat UBI 9. Follow README
commands and the ordered remaining work in docs/ROADMAP.md.

## Non-negotiable properties

- Final image based on digest-pinned UBI 9, with no package manager at runtime.
- Starts and stays non-root; no entrypoint privilege transition; unprivileged
  default listeners.
- Read-only root filesystem with explicitly declared writable paths; all Linux
  capabilities dropped and no-new-privileges in documented deployments/tests.
- Every build input pinned and verified: base images by digest, added RPMs by
  NEVRA and SHA-256 per architecture, upstream artifacts by SHA-256. Verify
  publisher signatures wherever published; state plainly where absent.
- No credentials, private keys, default passwords or reusable test credentials
  baked into images or examples. Public artifact-verification keys are build
  inputs only, never runtime trust anchors.
- Insecure upstream defaults fail closed. The explicit insecure opt-out remains
  documented and tested; never silently enable it.
- No FIPS, STIG, Kubernetes, OpenShift or other platform-support claims without
  matching evidence. The executable native-library temp path is explicit.
- Trivy AND Grype block fixed High/Critical findings on both native architectures
  under the owner-approved UBI-installable fix policy in SECURITY.md. Only RPM
  fixes proven absent from the build repositories may be deferred and reported.
  Fixed non-RPM findings and all query/evidence errors block. Never suppress a
  finding or add exemptions to get green; unfixed findings remain reported.
- Retain upstream notices. Trino is Apache-2.0, Temurin is GPLv2 with Classpath
  Exception; additional bundled components retain their own licences.

## Development and scope

Run local lint and unit tests; run real SQL and restricted-runtime tests on both
native architectures. Namespace restrictions must be reported, not worked around
with privileged containers. Keep CI Python requirements complete and hash-pinned,
including their .in source and transitive dependencies. Refresh locks only into
reviewable candidate output; never create human review/sign-off records.

The first increment has no release publication/signing workflow and creates no
tag or image version. Do not change GitHub settings or secrets. The trusted-main deferred tracker alone
may have issues: write; all other workflow permissions remain read-only.
`datopsis/container-hardening` is a draft reference only: no dependency, pinned
commit, conformance workflow call or release-eligible gating.

## Git conventions

Use a feature branch, Conventional Commit subjects and a PR against main. Never
force-push or merge without instruction. Do not add AI/tool attribution or
Co-Authored-By trailers. Do not commit downloads, credentials, keys generated by
tests, scanner databases, reports or SBOMs. Source-only changes do not create a
release version; see docs/VERSION.md.
